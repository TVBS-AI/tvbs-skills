# html-report engine build

`skills/html-report/scripts/am.mjs` is built from [doggy8088/answer-me-with-html](https://github.com/doggy8088/answer-me-with-html) (MIT, a zh-TW fork of [QingYunA/answer-me-with-html](https://github.com/QingYunA/answer-me-with-html)) with `upstream.patch` applied. The upstream source is not copied into this repo; `build.sh` fetches it at the pinned commit.

| File | Purpose |
|---|---|
| `UPSTREAM_SHA` | The upstream commit the bundle is built from (currently `3dde61b`, v0.5.11) |
| `upstream.patch` | Our changes to the upstream source |
| `expected-test-failures.txt` | Upstream tests that fail only because of the patch (they assert the upstream defaults) |
| `build.sh` | Fetch → patch → `npm ci` → bundle → run the upstream tests → copy the bundle and licenses into the skill |

## What the patch changes

1. **No colophon.** `colophon` defaults to off, so pages carry no "Generated by Answer me with HTML · ★ Star on GitHub" line above the title. The invisible `<meta name="generator">` tag stays.
2. **No update check.** `updateEnabled()` always returns false: the CLI never fetches the upstream `package.json` from GitHub and never shows the upstream update commands. Updates come through the tvbs-skills plugin.
3. **Own data folder.** `~/.tvbs-html-report` (and `tvbs-html-report-<uid>` in the system temp folder) instead of `~/.answer-me-with-html`, so settings, pages and state never mix with an upstream install.
4. The bundle banner names this build.

Everything else — components, layout, themes, the STE check, `patch`, `export` — is upstream behaviour.

## Rebuild

```bash
plugins/html-report/build/build.sh
```

Needs git, Node.js 20+ and npm. The script stops without copying anything if the failing upstream tests differ from `expected-test-failures.txt`.

## Move to a newer upstream commit

1. Put the new commit in `UPSTREAM_SHA` and run `build.sh`.
2. If `git apply` fails, re-make the four changes above on the new source and regenerate `upstream.patch` with `git diff -- src scripts/build.mjs`.
3. If the test diff fails, check each newly failing test: keep it in `expected-test-failures.txt` only when it asserts an upstream default the patch changes on purpose.
4. Read the upstream changelog for new network calls or new visible branding, and patch them out the same way.
5. Bump the plugin version and note the engine version in `CHANGELOG.md`.
