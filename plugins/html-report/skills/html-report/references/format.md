# 稿件與元件完整說明

SKILL.md 第 3、4 節是速查表，這份是完整說明。下文的 `am` 代表 `node "${CLAUDE_SKILL_DIR}/scripts/am.mjs"`。CLI 內建的英文說明和這份內容一致：`am help format`、`am help <元件>`。

## 稿件格式

````markdown
---
template: sheet        # sheet：多區塊網格（預設）；doc：單欄長文加大綱條
theme: auto            # auto（預設）：長文用 paper，有圖用 blueprint；也可寫 blueprint、shadcn、paper 或自訂主題
title: 頁面標題         # 也可以把「# 標題」寫在正文第一行
subtitle: 一句話說明
file: tcp-handshake    # 檔名，只能用英文字母和數字；標題裡沒有或只有很少英文字母時要寫
lang: zh-TW            # 頁面語言，見〈語言〉
cols: 3                # sheet 一列最多幾欄（整數），預設 3
outline: right         # doc 有 3 個以上章節時，大綱條在左邊或右邊：left 或 right（預設 right）
style: 80              # 寫作檢查：off、80（預設，只警告）、strict（不合格就不產生頁面）
mode: auto             # auto 跟隨系統、light、dark
source: RFC 9293       # 其他任何欄位都會顯示在標題下方的資訊列
---
導語，寫一兩句核心結論。

## A 區塊標題 {span=2 meta="右上角的小字"}
這裡寫一般 Markdown：段落、清單、表格都可以。

```flow LR
A -> B: 說明
```
````

區塊：

- 每個 `## ` 開頭的標題是一個區塊。字母 ID 可以不寫，會自動補上：前 26 個是 A 到 Z，之後是 `P27`、`P28`。
- 自己寫的 ID 必須唯一，而且和自動編號共用同一套：寫了 `## P27 標題`，後面的區塊就不會再自動拿到 `P27`。
- `span=2` 讓區塊佔兩欄，`rows=2` 讓區塊佔兩列，`bare` 拿掉區塊的標題列。`span` 和 `rows` 都要是整數。
- `span` 只是提示：頁面會依內容調整每區的大小，寬表格和寬圖不用寫。`rows` 只在一般網格生效（沒有 JavaScript、列印、窄螢幕時），瀏覽器排版會忽略它。

其他規則：

- 元件也可以寫成 `:::名稱 參數` … `:::` 區塊（VitePress、Docusaurus 的寫法），效果和 fenced code block 一樣，但只認得元件名稱；`:::note` 和單獨的 `:::` 仍當一般文字。
- 表格後面緊接 `{table sort}`，讀者就能點表頭排序，再點一次反向。右對齊的欄，以及每格都是數字或有效 ISO 日期的欄，依數值排序；其他欄依文字排序。數字可以有千分位逗號、`$` 前綴或 `%` 後綴。
- `{table filter}` 加上不分大小寫的全文篩選框，`{table sort filter}` 兩個都開。列印和匯出 PNG/PDF 時不顯示這些控制項。沒寫屬性的表格維持靜態。
- 元件表達不了時，可以用 ```` ```html ```` 或 ```` ```svg ```` 直接嵌入原始碼。頁面有內容安全政策（CSP）：區塊裡的腳本和行內事件處理器不會執行，也不會從網路載入任何東西。`html` 或 `svg` 區塊裡有 `<script>` 時，render 會帶稿件行號警告。
- `flow` 圖裡有連線穿過別的節點或別條連線的說明文字時，render 會帶行號警告並建議改法（通常是換方向，例如 ```` ```flow TB ````，或把圖拆開），頁面仍會寫出。
- `<host>` 這類佔位符會照文字顯示。句子裡只保留行內標記（`b`、`kbd`、`sup`、`a`、`span`、`br`、`img` 等）；會破壞頁面的標記（`script`、`style`、`iframe` 等）也照文字顯示。原始標記放進 `html` 或 `svg` 區塊，程式碼放進反引號。render 會列出每個被改動的標記。
- 有 3 個以上區塊的 `doc` 頁面會有大綱條：每個章節一小段刻度。滑過刻度會顯示章節標題，停留或點擊會展開完整清單，捲動時會標出目前章節。列印時不顯示。

## 元件

### flow：流程圖、架構圖（自動排版）

````markdown
```flow [TB|LR|BT|RL]
A -> B: 說明                  ← 實線；冒號後是連線說明
A -> B: 第一行\n第二行         ← 節點或連線說明裡寫 \n 會強制換行
A --> C                       ← 虛線
A -> B -> C                   ← 串接
A -> B & C                    ← 分岔
(開始)  {有效?}  [(資料庫)]  [含冒號: 的文字]   ← 圓角 / 菱形 / 圓柱 / 矩形
*重點節點                      ← * 開頭表示強調
group 群組名稱: B, C           ← 在這些節點外圍畫群組框
```
````

- 括號裡的文字就是節點本身，之後的行直接用這段文字指同一個節點。預設方向是 TB（由上到下）。
- 不接受 Mermaid 的節點 ID：寫 `[開始]`，不要寫 `A[開始]`，之後用 `開始` 指它。

### er：實體關聯圖（自動排版、鳥爪符號）

````markdown
```er [TB|LR|BT|RL]
*User                         ← 第 0 欄是實體；* 表示強調
  id PK                       ← 縮排是欄位：名稱 [型別] [PK|FK|UK]
  email string UK
Order
  id PK
  user_id FK -> User          ← FK -> 實體 會畫出多對一關聯
User 1--* Order: 下單          ← A <基數>--<基數> B: 說明（選填）
```
````

- 基數可寫 `1`、`0..1`、`*`、`1..*`。左端畫在左邊的實體，右端畫在右邊的實體。
- 欄位的 `FK -> 實體` 已經會畫關聯，關聯行可以不寫；寫了同樣兩個實體的關聯行，會取代自動畫的那條，並設定基數和說明。
- 型別可以省略：`email UK` 是有鍵、沒有型別的欄位。
- Mermaid 的 `USER ||--o{ ORDER` 會報錯，並顯示這個元件的正確寫法。欄位或關聯提到的實體，都要在第 0 欄寫出來。

### sequence：時序圖（角色之間的訊息）

````markdown
```sequence [num]
participants: A, B, C        ← 選填，固定角色順序
A -> B: 請求                  ← 實線
B --> A: 回應                 ← 虛線（回傳）
B -> B: 呼叫自己
note A: 單一角色的備註
note A, C: 跨多個角色的備註
== 階段分隔 ==
```
````

- 參數 `num` 會幫訊息編號。

### tree：層級樹（組織圖、縮排清單）

````markdown
```tree [list]
根節點 | 副標
  子節點
    孫節點 | 一行說明
  *強調的子節點
```
````

- 用縮排（空格或 Tab）表示層級，`標籤 | 說明` 會加上灰色說明。
- 一個根節點、2–4 個子節點時畫成組織圖；子節點更多或寫了 `list` 參數時畫成縮排清單；多個根節點時並排。
- 標籤支援行內 Markdown，例如 `` `第 1 節` 用詞 ``。

### timeline：時間軸、階段

````markdown
```timeline [h|v]
時間 | 標題 | 說明（選填）
*時間 | 標題        ← * 開頭表示強調
```
````

- 預設 6 項以內橫排，超過 6 項直排；`h`、`v` 參數可以強制方向。

### limits：數值對上限

````markdown
```limits
標籤 | 值 / 上限 | 單位（選填） | 說明（選填）
標籤 | 上限 | 單位      ← 只有上限：長條填滿到上限
```
````

- 值超過上限時，那一列變紅色。上限也可以寫成 `max 20`。

### chart：長條圖、折線圖、圓餅圖

````markdown
```chart bar unit=ms
            | p50 | p95
* Redis     | 12  | 40
Memcached   | 9   | 31
Postgres    | 28  | 95
```
````

- `chart` 後面接類型：`bar` 直條、`bar horizontal` 橫條、`line` 每個系列一條折線、`pie` 環狀圓餅。每一列是一個標籤，加上每個系列各一個數字，用 `|` 分隔。
- 第一列的值都不是數字時，它就是系列名稱，標籤格可以留空。一列有多個數字時一定要寫這一列，讀者才知道每種顏色代表什麼。沒寫時，每列只能有一個數字，也沒有圖例。
- `bar` 和 `line` 可以有 1–6 個系列。`bar` 最多 24 列，`line` 最多 60 點。
- 數字用一般寫法：可選的 `+` 或 `-`、數字、可選的小數點。不要加千分位。`bar` 和 `line` 的負數畫在零線下方。
- `bar` 的座標軸一定從 0 開始，不會截斷。`line` 的座標軸可以不從 0 開始；最小值不到最大值的三分之一，或數值碰到、跨過 0 時，才從 0 開始。
- `unit=` 會原樣加在刻度和數值後面：`unit=%` 顯示 `40%`，`unit=" ms"` 顯示 `40 ms`。區塊標題就是圖表標題，所以沒有 `title=`。
- 標籤前的 `*` 會強調那一列。`bar` 只有一個系列時，那根長條用強調色；有多個系列時保留系列色，其他列變灰。`line` 那一列的點變大並顯示數值，加一條細虛線參考線。`pie` 那一塊保留顏色，其他塊變灰。
- 多個系列時有圖例。12 根長條以內，長條上會顯示數值。
- `line`：只有一個系列、12 點以內時，每個點都顯示數值；更多時只有強調的那一列顯示。
- `pie`：每列一個數字，數值要 0 以上，至少一個大於 0，最多 6 塊。從 12 點鐘方向開始，依寫的順序順時針排列。旁邊的清單列出每塊的數值和百分比，中間寫總數。寫 `unit=%` 時數值本身就是占比，不再算百分比，中間留空。
- 圖下方有一張預設收合的表格，列出所有數字，螢幕閱讀器讀得到，讀者也可以複製。
- 格數不對、值不是數字、圓餅有負數或全是 0、超過上限，都會報錯，並附行號和正確寫法。

### callout：結論、提示、警告

````markdown
```callout <info|ok|warn|err> [標題]
內容（Markdown）
```
````

- 第一個參數不是類型時，整串參數都當標題，類型是 `info`。

### kv：鍵值表、標題區塊

````markdown
```kv [cols=2]
欄位: 值
* 寬欄位: 值        ← * 開頭：獨佔整列、字比較大
```
````

- 在第一個冒號（半形 `:` 或全形 `：`）切開，值裡可以再有冒號。

### annot：逐段講解句子（底線括號加說明）

````markdown
```annot
# 標題 | 右側說明（選填）
句子內容，[要說明的片段]{說明}，[寫錯的片段]{!紅色說明}。
> 下方的圖說（選填）
```
````

- 每個 `#` 開始一組，一組可以有多個句子。說明重疊時，會自動移到不同列。

### ask：讀者在頁面上做的決定（由「回覆」收集）

````markdown
```ask [multi]
問題，一句話
* 你建議的選項 | 選填說明   ← * 會標上「建議」；一開始都不會被選取
- 其他選項 | 選填說明
```
````

- 第一行是問題。每個選項以 `*` 或 `-` 開頭，寫 2–6 個。
- 單選要有、而且只能有一個 `*`。`multi` 允許多選，`*` 標出你建議的那些。
- 放在答案會影響的那個區塊裡。

## 變更標記：呈現計畫改了什麼

`flow`、`tree`、`er` 的行首可以寫 `+ `（新增）、`- `（刪除）或 `~ `（修改），後面要有空格：

````markdown
```flow LR
Client -> Gateway
+ Gateway -> [(Cache)]: 查詢
+ Cache -> Service: 沒命中
- Gateway -> Service
~ *Service
```
````

- 頁面的 Changes 檢視用主題的 ok 色畫新增、淡化並刪除線畫刪除、warn 外框畫修改，並在節點上加 +、−、~ 標章。圖下方有統計列和 Before / Changes / After 切換。
- `flow`：記號套用到那一行的每條連線。節點只出現在 `-` 行就算刪除，只出現在 `+` 行就算新增，也出現在沒標記的行就算沒變。沒有箭頭的 `~ 節點` 表示這個節點有修改。有箭頭的行不能用 `~`：用 `-` 刪掉舊的、`+` 加上新的，改連線說明也是這樣。`+ group 名稱: A, B` 可以標群組框。
- `tree`：記號寫在縮排之後。`+` 或 `-` 節點的子節點會跟著套用；子節點標了不同記號會報錯。`~` 只標一個節點，不會往下套用。標籤本身以 `- ` 開頭時，寫 `\- item`。
- `er`：實體只由自己那一行標記；標了欄位不會標到實體。`+` 或 `-` 實體的欄位會跟著套用。`~` 標的欄位不會顯示舊值。FK 欄位畫出的關聯跟著那個欄位的記號；關聯行用自己的記號，不能用 `~`。
- 記號和 `*`、各種形狀的括號可以一起用。行首是記號加空格的，一定會被當成記號；`flow` 的節點名稱本身以 `- ` 開頭時，寫成 `[- Gateway]`。

## 程式碼區塊與 diff

專案裡已有的程式碼，直接引用檔案，不用手抄：

````markdown
```ts src=server/routes.ts lines=18-30 hl=22
```

```ts title="limits.ts · sketch"
export const LIMIT = 50
```
````

- 語言名稱不是元件名稱的 fence，都是程式碼區塊，有標題列和複製按鈕。
- `src=` 讀取檔案，區塊內容留空。路徑從目前目錄讀取，只能引用目前目錄裡的檔案。`lines=18-30`（或 `lines=18`）選要顯示的行，行號和檔案一致；不寫就引用整個檔案。
- 標題列顯示 `路徑:行號`，有寫 `title=` 時顯示 title。還不存在的程式碼，在 title 寫 sketch。
- `hl=22` 或 `hl=20-22,25` 依顯示的行號強調。`start=38` 讓手寫區塊的行號從 38 開始。
- 10–40 行最能說明重點：超過 40 行會警告，超過 200 行會報錯。
- 依慣例存放密鑰的檔案（`.env`、`*.pem`、`id_rsa`、`.ssh/`、`.git/` 等），以及任何內容看起來像密鑰或 token 的檔案，都會被拒絕。
- render 會列出嵌入的每個檔案。頁面會記住路徑；`am patch` 會重新讀取檔案，檔案已經移走時，就用頁面裡原有的那份。

要呈現一處修改，把 unified diff 貼進 `diff` fence：

````markdown
```diff file=src/code.js
@@ -60,3 +60,3 @@
 export function parseCodeArgs(args) {
-  const attrs = parseAttrs(args);
+  const attrs = parseAttrs(args, { diff: true });
   const opts = {};
```
````

- `+` 開頭是新增（綠色），`-` 是刪除（紅色），空格開頭是前後文；空行也算前後文。
- `@@ -60,3 +60,3 @@` 開始一個 hunk，顯示成一條細分隔列，並決定新舊兩欄行號。沒有 `@@` 時，`start=N` 從 N 開始編號；兩者都沒有就不顯示行號。
- `file=` 顯示在標題列，語言標記取自副檔名；沒寫時用 `+++ b/path` 那一行的路徑；`title=` 優先於兩者。標題列後面會顯示統計，例如 `+1 −1`。
- `hl=` 用新檔案那一側的行號，而且要有行號（`@@` 或 `start=`）。
- `diff --git`、`index`、`---`、`+++` 和 `\ No newline at end of file` 可以保留，但不會畫出來。
- 只有 `...` 或 `…` 的省略行會報錯，因為無法知道跳過了幾行：拆成兩個 hunk，各有自己的 `@@`。hunk 行數和 `@@` 標頭不符會警告。`diff` 還不支援 `src=`，請直接貼 diff。其他限制和程式碼區塊相同。

## 圖片

````markdown
![遊戲的三種觀戰視角](/絕對路徑/screenshot.png)
````

- 圖片單獨寫一行。alt 文字會變成圖說，寫這張圖顯示什麼；寫作檢查也會讀它。
- 用絕對路徑。相對路徑從稿件檔案所在的資料夾讀取；稿件來自 stdin 時，從目前目錄讀取。路徑有空格也可以。
- 支援 PNG、JPG、GIF、WebP、AVIF 和 SVG，每個檔案 5 MB 以內。圖片會嵌進頁面，頁面仍是一個能離線打開的檔案。寬圖會縮到區塊寬度。
- 遠端圖片不會載入：頁面會擋掉所有遠端請求，`http(s)` 或 `//` 網址只會顯示空白，render 也會警告。先把圖片存成檔案，再寫本機路徑。`data:` URI 可以用。
- 頁面會記住每張圖片的路徑。`am patch` 會重新從檔案嵌入圖片；檔案已經移走時，就用頁面裡原有的那份。
- 這個工具不產生圖片。不要捏造圖片。

## 數學式

````markdown
頂點權重：$w(v)=\prod_{u\prec v}N_u^{-1}$。

$$
\widehat g=\sum_{i=1}^{n} w_i\widehat A_i\nabla_\theta\log\pi_\theta(a_i\mid s_i)
$$
````

- `$…$` 是行內公式，要寫在同一行。區塊公式是：單獨一行 `$$`、幾行 TeX、再單獨一行 `$$`；也可以寫成一行 `$$ E = mc^2 $$`。區塊公式裡不能有空行。
- 產生頁面時就排好版（Temml，輸出 MathML），頁面不需要腳本，也不用連網。公式沿用正文顏色。
- 比區塊寬的公式會在區塊內橫向捲動。行內公式在 Chrome 和 Firefox 會在 `=`、`+` 後面換行，Safari 不會；長公式請放區塊。
- 不是公式的錢字號會保持原樣：`$5 and $10`、`$5-$10`、`$PATH:$HOME` 都不會被當成公式。要寫錢字號就用 `\$`。寫 `$n$-th`，不要寫 `$n$th`。
- 公式可以用在段落、清單、表格、引言、標題、`callout`、`kv`、`ask`、`timeline` 和 `tree` 的文字。行內程式碼、程式碼區塊和圖（`flow`、`er`、`sequence` 等）不支援。表格格子裡寫 `\vert x \vert`，不要寫 `|x|`。
- Temml 看不懂的 TeX 不會讓產生失敗：頁面照常寫出，公式用紅色等寬字顯示原始 TeX，render 會帶行號警告。改好後用 `--replace` 再產生一次。
- `\ref`、`\eqref`、`\label` 不支援，會警告；`\tag{1}` 可以用在區塊公式。
- 寫作檢查會跳過 TeX。

## 語言

稿件語言決定頁面的 `<html lang>`、按鈕文字、字型和寫作檢查規則。可以在稿頭用 `lang:` 指定；沒寫時依正文的文字判斷。

| `lang:` | 文案與字型 |
| :--- | :--- |
| `zh-TW`、`zh-Hant`、`zh-HK` | 繁體中文，繁體字型優先 |
| `zh`、`zh-CN`、`zh-Hans` | 簡體中文 |
| `en`、`en-US` 等 | 英文 |
| `ja` | 日文 |
| `he` | 希伯來文，頁面由右到左 |
| 其他，例如 `fr`、`ko` | 英文文案，`<html lang>` 照你寫的 |

- 自動偵測時，漢字預設判斷為簡體，只有「只出現在繁體的字」比「只出現在簡體的字」多時，才判斷為繁體。所以繁體中文稿件**一定要寫 `lang: zh-TW`**，短稿或用字平常時尤其容易誤判。
- `am patch` 會保留原頁的語言，除非新稿件有寫 `lang:`。
- 寫作檢查依語言套用：中文和英文有各自的詞表與規則；日文和其他語言只檢查句長和段長。

## 回覆、評論與標註（讀者端）

- 每個頁面都有「回覆」按鈕。讀者可以在任一區塊寫評論（區塊標題列的對話框按鈕），也可以作答 `ask`，最後把一段 Markdown 回覆複製給 agent。
- 「標註」按鈕打開後，讀者可以點段落、清單項、引言、程式碼區塊、表格或公式區塊，選一個類型（建議、保留、疑問、關注），也可以寫一句批註。頁面標題和區塊標題不能標註，請用區塊評論。
- 回覆會寫明每個決定是讀者改過的、確認了建議，還是沒有作答。評論和批註以 `>` 引用的形式回傳。
- 在本機打開（`file://`）時，選擇和評論重新整理後還在。上傳到 company-wiki 後，頁面在沙盒裡不能使用瀏覽器儲存空間，重新整理後就會消失。
- 複製失敗時，頁面會提示改用 Cmd/Ctrl+C 手動複製。

## 命令列

```bash
am render notes.md                              # 產生並用瀏覽器打開（依 open 設定）
am render notes.md -o out.html --no-open        # 指定輸出檔案，不自動打開
am render notes.md --theme shadcn               # 這一次換主題（也有 --template、--style、--mode）
am render - <<'AM_EOF' … AM_EOF                 # 從 stdin 讀稿件，agent 都這樣呼叫
am patch page.html --panel "區塊標題" < panel.md # 只換一個 ## 區塊，覆寫原檔
am lint notes.md                                # 只做寫作檢查
am list                                         # 列出範本、主題和元件
am config                                       # 查看設定
am export page.html --pdf page.pdf --png out/   # 匯出 A4 PDF 和 PNG 切片
am clean --dry-run                              # 預覽要清掉哪些舊頁面
```

檔名與暫存稿：

- 沒有 `-o` 時，頁面命名為 `<名稱>-<時間>.html`。名稱取自稿頭的 `file:`；沒有 `file:` 或其中沒有英文字母和數字時，取自標題：只留小寫英文字母和數字，其他字元合併成一個 `-`，最多 24 個字元，都沒有時用 `page`。所以全中文標題的稿件要寫 `file:`。
- 稿件來自 stdin 而且有錯誤或警告時，會存成資料夾裡的 `drafts/<名稱>-<時間>.md`，輸出裡有 `draft: <路徑>`。之後沒有警告地產生時，會自動刪掉。
- `--replace <頁面>` 會在新頁面寫好後刪掉上一版，所以每個答案在 `pages/` 裡只留一份。
- 預設資料夾 `~/.tvbs-html-report/` 只有你自己的帳號能進入（權限 0700）。環境變數 `AM_HOME` 可以改位置。

匯出：

- `--pdf`：依頁面的列印樣式印成 A4，保留背景色，不加頁首頁尾。
- `--png`：用 1200 CSS px 寬、2 倍像素渲染，隱藏工具列和回覆按鈕，切成每張最高 1800 CSS px 的圖，切口落在區塊之間。目錄不存在時會建立。
- 需要 Chrome、Chromium 或 Edge，以及 Node.js 22 以上；不在常見位置時，用 `AM_CHROME` 指定。PDF 和 PNG 是圖片，回覆、主題切換等互動功能都不能用。
